# 手动备份与恢复：架构审查与 UX 改进（V10.67，2026-11-14）

> 起因：真机测试（截图 IMG_9420–9422）发现，备份直接弹出 iOS 共享面板，之后问「备份文件存好了吗？」；恢复直接打开「文件」选择器。普通用户看不懂这两步。
> 本文先写**现状审查**（改动之前的事实），再写**改了什么**。恢复的含义**保持「替换」**，没有改成合并（需要用户确认后才能改）。

## 一、现状审查（V10.66 之前）

### 1. 备份文件里有什么

| 项目 | 现状 |
|---|---|
| 格式 | 一个 JSON 文件 `Capiday-Backup-日期.json`：`{ format: "little-days-backup", version: 1, createdAt, complete, missing?, state, media: [...] }`（`media.mjs` `backup()`） |
| `state` | 整份手帐：手帐本、每一天和每一页（文字、排版、图层、手绘）、草稿、日历标记、计划、习惯和打卡、Captain 的数据、页面音乐的编号 |
| 媒体 | **包含**页面用到的每一张照片、每段视频、每段录音、封面图：每个文件以 base64 data URL 写进 `media[].data`，**比原文件大约 33%** |
| 不包含 | 没有被任何页面用到的媒体；外观主题和语言（`little-days.theme` / `language`）；每日提醒；App 锁；个人资料（`little-days.account` 的名字、头像）；音乐音量；本机事件日志；每日快照和恢复前快照 |
| App 自带素材 | 示例照片、贴纸、背景、音乐以编号保存（`photo:` / `scene:` / 音乐 id），恢复时由 App 自带，不在文件里 |
| 大小上限 | 媒体总量 100 MB（`MAX_BACKUP_MEDIA_BYTES`）：超过时**整份备份拒绝**，不会悄悄漏掉文件。恢复时文件不超过 150 MB，单个媒体不超过 50 MB |
| 读不出的文件 | C2：列出来让用户选择；继续的话，文件写明 `complete: false` 和 `missing` 清单 |
| 内存 | 导出和导入都要把整份文件放进内存（字符串、解析结果、Blob），峰值约为文件大小的 3 倍。接近 100 MB 媒体时在 iPhone 上可能不稳定。S1-2 的 `.capiday`（ZIP、流式）会解决 |

用户截图里 21.4 MB 的文件，正好对应「设置」里显示的约 15.3 MB 本机媒体（×1.33 再加上文字部分）。

### 2. 跨设备恢复

- 恢复按内容写入媒体（S1-1：按 id 和 SHA-256 判断，相同内容不重复写），然后重新映射引用，所有手帐设为私人。
- **已验证**：浏览器里恢复到一个全新的空环境（`tests/v121`、`v161`）；同一设备上恢复两次、失败回滚、中断恢复（`v161`）。
- **未验证**：真机之间（iPhone A 备份 → iPhone B 恢复）；接近 100 MB 的大文件在真机上的内存表现。
- 依赖：恢复的设备上 App 版本不能更旧（要能认得 `schemaVersion 1` 和其中的素材编号）。

### 3. 自动快照与手动备份

| | 每日快照 | 恢复前快照 | 手动备份 |
|---|---|---|---|
| 在哪里 | 这台设备的 IndexedDB | 这台设备的 IndexedDB | 用户选的位置（「文件」、iCloud 云盘、电脑） |
| 有没有媒体 | 没有 | 没有（媒体留在本机媒体库） | **有** |
| 丢手机 / 删 App 后 | 没了 | 没了 | 还在（如果没有存在「我的 iPhone」里 App 自己的文件夹） |
| 用途 | 手帐数据出错时的退路 | 7 天内撤销一次恢复 | 换手机、重装 |

### 4. 现有交互的问题（截图）

1. **共享面板意思不清**：外壳把下载的备份放进 App 自己的 Documents，然后弹出 `UIActivityViewController`。里面有 AirDrop、信息、微信、拷贝、存储到「文件」……用户要自己猜该点哪个。**Documents 是 App 自己的文件夹，删除 App 时会一起删掉**，所以文件留在那里不算备份。
2. **「存好了吗？」只能靠用户回答**：共享面板不会把结果告诉网页，所以 App 只能问用户，并且把用户点的「存好了」当成「已备份」记下来。
3. **恢复没有说明**：点「从备份恢复」立刻打开文件选择器，用户不知道会发生什么（替换、合并、能否撤销）。S1-1 的预览出现在**选完文件之后**。
4. 「导出完整本机备份」这几个字太技术；文件选择器里显示的是 `.json`。

## 二、改了什么（V10.67）

### 备份：备份我的手帐

1. 设置 → **备份我的手帐**（原「导出完整本机备份」）。
2. 一个面板：
   - 一句话说明用途；
   - **会备份**：本数、天数、页数，草稿、计划、习惯和 Captain，以及照片、视频、声音的数量（从这本手帐里实际数出来）；
   - **文件大小**：按本机媒体的实际大小估算；
   - **不会备份**：外观和语言、每日提醒、App 锁、个人资料，快照只留在本机。
   - 面板里不出现 JSON 这类技术词。
   - 超过 100 MB 媒体时，在这里就说明，按钮不能点，不会先做到一半再失败。
3. **iPhone App：「选择保存位置」**
   - 外壳先把文件写到临时目录，然后打开系统自己的「存储到文件」面板（`UIDocumentPickerViewController(forExporting:asCopy:)`），不再用共享面板。
   - 等待时提示：推荐存到 iCloud 云盘或电脑，不要只存在「我的 iPhone」。
   - **系统会告诉网页结果**：
     - **存好了**：外壳读回存好的那份文件，**大小核对一致**才记为「系统已确认」，并带上文件夹名。存在 iCloud 云盘时会说明：上传到云端由 iCloud 完成，Capiday 看不到上传进度（不承诺「已上传」）。
     - **存了但读不回来**：记为「已交给系统，未能核对」。
     - **取消**：不记录，提示「没有保存，这次备份没有记录」。
     - **空间不够或写入失败**：说明原因，不记录，并说明手帐没有任何改动。
     - 临时文件用完即删。
4. **浏览器（在线链接、Safari）：「下载备份文件」**
   - 浏览器不会告诉网页文件存到了哪里，所以面板说明这一点，由用户点「我已存好」。
   - 记为「你确认已存好」，设置里也这样显示，**不显示为系统确认**。点「还没有」不记录。
5. 设置里「上次备份」后面会写明是谁确认的：系统确认（带文件夹名）、未能核对，或者你确认。

### 恢复：从备份恢复

1. 设置 → 从备份恢复 → 先显示一段简短说明：
   - 选一个之前存好的备份，开始前会先告诉你里面有什么；
   - **恢复会替换这台设备上现在的手帐，不是合并**；
   - 替换前自动保留现在的手帐，7 天内可撤销。
2. **选择备份文件** → 打开 iOS「文件」选择器。
3. 之后是 S1-1 已有的流程：
   - 校验格式、版本、完整性和每个媒体；
   - 预览备份日期，以及天、页、照片、视频、声音的数量，和现在的手帐对比；
   - 「继续」后再确认一次；
   - 快照写入并读回；
   - 先写媒体，一次切换，读回核对；
   - 失败就回到原来的手帐。
4. 新增：**空间不够**时单独说明（「这台设备的空间不够……你现在的手帐没有改动」），不再只是笼统的失败。

### 没有改的

- 恢复的含义（替换），以及 S1-1 的二次确认。
- 备份文件的格式和内容（仍是 v1 JSON）。`.capiday` 格式在 S1-2。
- 现有数据：存储键、数据结构、媒体都没有迁移。

## 三、验证

- 网页（Chromium）：`tests/v163-browser.cjs`，分浏览器和 iPhone App 两条路径。iPhone App 的系统面板结果由测试按外壳的同一接口（`window.capidayBackupSaved`）给出。
- 真实触控（XCUITest，模拟器）：`tools/mac/uitest/DrawUITests.swift` `testBackupRoundTrip` 依次做：取消、存到「我的 iPhone」、用「文件」选择器读回那份文件、出现预览。
- 真机：见 `agent.md` V10.67 的手动验收清单。
